# Live Presage service

This local Windows demo keeps the native SmartSpectra SDK outside Vite. The service
uses SDK 3.3.0 and Node 24. It listens only on 127.0.0.1:8787. Starting this process
alone does not open the camera or start a Presage measurement session.

## Setup on this computer

Dependencies have been installed. A blank ignored `.env` file has been prepared.

1. Open `sensing-service/.env` in a text editor. Fill in `PRESAGE_API_KEY=` with
   your key. Do not put it in frontend configuration, chat, screenshots or Git.
2. Run `sensing-service/start.cmd` (double-click or run from your terminal).
   Keep that terminal open. The launcher uses Node on PATH, or Codex's bundled
   Node when available. After changing `.env`, stop the service with Ctrl+C and
   restart it.
3. Open EchoShift's Vite development page on port 5173 or 5174. Demo Mode is default.
4. Select **Start live sensing**. This opens the webcam through the native service
   and may consume Presage credits. Windows must allow desktop apps to use the
   camera. Close other camera apps if necessary.
5. Face the camera in good lighting, with your chest visible. Unknown is expected
   during warmup. Only reliable, fresh measurements reach the game engine.
6. Select **Stop live sensing** to end the session and return to Demo Mode. Close
   the service terminal with Ctrl+C when finished.

For a new checkout with Node 24 installed:

```powershell
cd sensing-service
npm ci --ignore-scripts
Copy-Item .env.example .env # only if .env does not already exist
# Edit .env locally, then:
npm start
```

If your game uses another port, add its exact localhost origin to ECHOSHIFT_ORIGINS.
The current App expects service port 8787. PRESAGE_CAMERA_INDEX selects the native
camera device, starting at 0. The service's native camera does not produce a browser
permission dialog; use Windows camera privacy settings for desktop apps.

## Measurements and credit behavior

Only BREATHING_RATE (2) and PULSE_RATE (15) are requested. Missing fields can mean
that the account's subscription does not include a metric; the SDK can omit such
fields without reporting an error. Check the developer portal/sponsor if warmup
never produces usable data. No engagement score, emotion label or medical conclusion
is generated by Presage here: gameplay states are computed by EchoShift.

The service requires validation code kOk plus stable samples, confidence within
0–100, and a fresh timestamp. SDK timestamps are documented as epoch microseconds;
they are converted to epoch milliseconds. Duplicate field samples are discarded,
and combined samples use the oldest included timestamp. No stale sample gets a
new timestamp. Native/source values are not logged or persisted.

No automatic reconnection or paid retry is performed. An explicit Start is needed
after failure. Credit pricing and free-tier entitlements are account-dependent;
this app does not estimate how long 100 credits lasts.

## Cleanup and transport

The stream owns one session. Stop, disconnect, errors and shutdown release the SDK.
A browser heartbeat renews a 15-second lease; a frozen or closed tab therefore
cannot leave sensing running indefinitely. Background-tab throttling can end a
session; return to the game and explicitly restart it. Another tab receives Busy.
Cleanup failure blocks reuse until the service restarts.

Origin, Host, and ownership-token checks restrict access to the configured local
game. The API key stays in `.env` in this process. SDK logs are disabled and public
errors use fixed codes. This is a local demo bridge, not a public camera backend.

## Verification

```powershell
node --test test/*.test.mjs
```

Tests cover normalization, live lifecycle with a fake native boundary, real HTTP
transport, blocked origins, lease expiry, shutdown and installed SDK exports/protobuf
decoding. Import/export checks do not start a camera. Browser QA exercises the real
App and transport using a fake SDK boundary. Actual camera capture, account access,
measurement cadence and credit usage still require your first explicit live test.
